# 중첩 클래스
클래스 안에 선언한 클래스. 바깥 클래스와 **가깝게 묶어서** 쓰려고 만듦

---
## 4가지 모양
```java
class Outer {
    private String name = "동태";

    // 1. static 중첩 클래스
    static class StaticNested { }

    // 2. 내부 클래스 (inner)
    class Inner {
        String hello() { return name; }   // 바깥 필드를 바로 사용
    }

    void method() {
        // 3. 지역 클래스 : 메서드 안에서만 사용
        class Local { }

        // 4. 익명 클래스 : 이름 없이 한 번만 사용
        Runnable r = new Runnable() {
            public void run() { System.out.println("실행"); }
        };
    }
}

new Outer.StaticNested();       // 바깥 객체 없이 생성
new Outer().new Inner();        // 바깥 객체가 먼저 필요
```

| 종류 | 설명 |
|---|---|
| static 중첩 | 바깥 객체와 **연결 없음**. 이름만 `Outer.StaticNested`로 묶인 독립 클래스 |
| 내부 클래스 | 바깥 객체에 **붙어서** 생성됨. 숨은 참조로 바깥 필드를 자기 것처럼 사용 |
| 지역 클래스 | 메서드 안에 선언. 그 메서드 안에서만 사용 |
| 익명 클래스 | 이름 없이 `new 인터페이스() { }`로 바로 구현. 지금은 람다로 대체됨 |

---
## 비교
| | static 중첩 | 내부 클래스 | 지역 | 익명 |
|---|---|---|---|---|
| 바깥 객체 필요 | X | O | O (인스턴스 메서드 안이면) | O (인스턴스 메서드 안이면) |
| 바깥 인스턴스 필드 | X | O | O | O |
| 사용 범위 | 어디서나 | 어디서나 | 메서드 안 | 선언한 그 자리 |
| 이름 | 있음 | 있음 | 있음 | 없음 |

## 장단점
**static 중첩**
- 장점 : 바깥 객체에 의존 안 함, 숨은 참조가 없어 메모리 누수 위험 없음, 이름 정리와 `private` 숨김 가능
- 단점 : 바깥 인스턴스 필드를 못 씀

**내부 클래스**
- 장점 : 바깥 필드를 바로 사용
- 단점 : 바깥 객체를 계속 붙잡아서 **메모리 누수** 가능, 생성이 번거로움

**지역, 익명**
- 장점 : 쓰는 자리 바로 옆에 코드를 둘 수 있음
- 단점 : 코드가 지저분해지기 쉽고, 익명은 람다가 더 간결함

- 바깥 객체의 필드가 필요 없으면 **기본은 static**
- 로직이 커지면 책임이 커진 신호라서 밖으로 분리

---
## 어디서 많이 쓰나
| 상황 | 예 |
|---|---|
| 요청/응답 DTO | `MemberDto.Request`, `OrderResponse.Item` |
| 도메인 enum | `Order.Status`, `Member.Role` |
| 빌더 | `Member.Builder` |
| 설정 프로퍼티 | `AppProperties.Jwt` |
| 테스트 | `@TestConfiguration static class`, `@Nested` |
| 자료구조 | `LinkedList.Node`, `Map.Entry` |
| 반복자 (내부 클래스) | `ArrayList`의 `Itr` |

- 직접 짤 때는 대부분 **static 중첩** (그 클래스 전용의 작은 데이터 타입)
- 여러 곳에서 쓰이는 타입은 밖에 따로 둠
