## 세부 내용
- 트랜잭션
  - 여러 작업을 전부 성공 아니면 전부 취소로 묶는 단위 (commit / rollback)
  - ACID : 원자성, 일관성, 격리성, 지속성
  - 스프링은 `@Transactional`로 처리 (정상 종료 시 commit, 런타임 예외 시 rollback)
- CRUD
  - Create / Read / Update / Delete. 거의 모든 서비스의 기본 동작
  - SQL(INSERT, SELECT, UPDATE, DELETE), HTTP(POST, GET, PUT, DELETE)와 대응
  - 구성 : Controller → Service(트랜잭션) → Repository → DB
- DTO와 Entity
  - Entity : DB 한 줄을 자바 객체로 표현한 것 (JPA가 관리), 리포지토리와 서비스 안쪽
  - DTO : 클라이언트와 주고받는 값만 담은 객체, 컨트롤러의 파라미터와 반환값
  - 서비스에서 DTO → Entity, Entity → DTO로 변환
  - 분리 이유 : 비밀번호 같은 값 노출 방지, API가 DB 구조에 묶이지 않게, 순환 참조와 지연 로딩 문제 방지

> [!success]- Q. 멀티스레드나 스케줄링을 아직 안 했는데 지금 공부해야 하나?
> 깊게는 나중이어도 된다. 다만 서버가 요청마다 스레드로 돌아가서 공유 상태가 위험하다는 감각은 일찍 잡기. 스프링 DB, 트랜잭션 다음에 동시성 문제로 연결해서 보면 좋다.

> [!warning]- Q. Entity는 DB에 요청을 보내고 받을 때 쓰는 건가? DTO는 정확히 어디서 쓰이나?
> Entity는 DB 한 줄을 객체로 표현한 것이라 리포지토리에 넘기고 받을 때 쓴다. DTO는 컨트롤러의 입구와 출구(파라미터, 반환값)에서 쓴다.
