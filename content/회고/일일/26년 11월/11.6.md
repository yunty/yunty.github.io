## 세부 내용
- 빈 스코프는 빈이 존재할 수 있는 범위를 나타냄
	- 싱글톤, 프로토 타입 등이 있음
		- 싱글톤 : 스프링 컨테이너 시작부터 종료까지 / 가장 넓음
		- 프로토타입 : 프로토타입 빈의 생성과 의존관계 주입까지만 / 가장 짧음
		- 웹 관련 request, session, application 등
- 프로토타입 빈은 **요청할때** 생성하고, 주입하고 반환 스프링 컨테이너에서 관리x
	- 관리의 책임은 반환 받은 클라이언트가 있으며 preDestory같은거 적용 x / but 의존주입 이후 postConstruct는 실행됨
- 싱글톤을 생각해보면 1개만 만들어서 스프링 컨테이너에서 요청이 들어올때마다 생성해둔 1개의 객체(싱글톤 객체)를 반환하기 때문에 시작부터 끝까지 사용하는것
- @Scope()를 통해 지정가능하지만 안쓰면 기본이 싱글톤
- 싱글톤 빈에서 프로토타입을 주입받는 상황이면(provider패턴 미사용) 결국 생성 후에 받은값을 싱글톤 빈에서 유지하고 있기때문에 프로토타입일지언정 싱글톤 처럼 사용된다.
- 의존관계를 주입받는게 DI(Dependency Injection)이라면 반대로 내가 찾아서 사용하는게 DL(Dependency Lookup / 의존관계 조회)이다.
- 저렇게 싱글톤 객체 내에서 요청때마다 프로토타입을 생성하는 방법을 지원해주는 방식이 ObjectProvider, ObjectFactory, JSR-330 Provider
	- ObjectProvider<프로토타입> 타입으로 받아서 .getObject로 프로토타입을 받음 즉 매번 새로 프로바이더를 통해 받을 수 있음(프로바이더가 스프링컨테이너를 통해 해당 빈을 찾아서 반환해줌)
		- ObjectFactory를 상속받았으며 스트림 처리등의 편의 기능이 더 추가됨
	- ObjectFactory는 Provider보다 더 단순한 기능만 있음
	- JSR-330 Provider(jakarta.injcet.Provider)
		- 별도의 라이브러리 추가 필요함
		- .get()을 통해 얻을 수 있음 사용방법은 ObjectProvider랑 동일
- 웹 스코프
	- Request : 요청이 들어오고 나갈때 까지만 유지

## 헷갈렸던 것 / 질문
%%  풀렸으면 success, 아직 헷갈리면 warning. 제목(Q)만 보고 답을 먼저 떠올린 뒤 펼쳐서 확인하기 %%
> [!success]- 콜백이라는게 스프링이 관리할때만 알려주는게 맞는지
> 맞음 따라서 스프링의 관리를 벗어나는 프로토타입이 종료콜백을 받지못하는것임.

>[!success]- provider 사용안했을때의 싱글톤에서 프로토타입 객체를 주입 받으면 그 관리의 책임은 싱글톤 객체한테 있는것인가
>맞음 종료든 뭐든 관리가 필요하면 싱글톤 객체가 해야함

>[!success]- 프로토타입 객체 관리의 책임이 클라이언트한테 있다는데 왜인지, 클라이언트한테 어떻게 책임을 넘길수가 있는지
>일단 서버-클라이언트에서의 클라이언트를 의미하는것이 아닌 스프링 컨테이너에 요청을 하는 코드 혹은 객체쪽을 클라이언트라고 봐야하며 실제로 서버-클라이언트 관계에서 클라이언트가 책임을 가져가는 상황은 거의 없음(스프링 빈에 한해서)

>[!success]- 관리의 책임이 넘어간다는게 뭔데?
>객체의 생명주기를 책임지는것 생성, 의존관계 연결, 보관, 콜백 호출, 소멸등을 얘기하고 프로토타입이 이제 스프링에서는 의존관계 연결까지만 책임지고 그 뒤로는 **관리의 책임을** 요청한 클라이언트쪽으로 넘기는것이다.

>[!success]- 프로토타입 객체일지라도 빈에서 가지고 있어야 원할때 주입이 가능한데 그럼 beanDefinition만 채워두고 필요할때마다 생성하는건가? 그걸 해주는게 @Scope인건가?
>맞음, 원래는 컨테이너 시작 시에 인스턴스 생성 후 보관인데 @Scope를 통해 빈 스코프를 설정해 두었기 때문에 이를 통해서 요청이 들어올때만 생성하고 반환하고 인스턴스의 참조값을 따로 보관하지 않음

>[!warning]- 아니 왜 스레드가 같은것들끼리 어떻게 동일한 객체를 공유하면서 사용하는거지? 그리고 요청객체에 저장되는 빈은 뭐야 // 스레드가 흐름이라는건 이해하는데 정확하게 이친구가 무엇인지 정리가 안된다.
