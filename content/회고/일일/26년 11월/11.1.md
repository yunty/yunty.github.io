## 세부 내용
정리한 글 : [[사람이 컴퓨터를 조작하는 방법]]
- 컴퓨터와 0과 1
  - 컴퓨터(Computare)는 원래 계산하는 사람을 가리켰고, 이후 계산하는 기계를 뜻하게 됨
  - 진공관 : 음극을 가열하면 전자가 튀어나와 양극으로 이동, 그리드에 -전압을 걸면 전자를 밀어내 차단. 흐름 = 1 / 차단 = 0 (어느 쪽을 1로 할지는 회로가 정함)
  - 트랜지스터 : 소스·게이트·드레인. 게이트 전압으로 전자의 길(채널)을 열고 닫는 스위치, 가열 불필요
  - 스위치 → 게이트(연산·제어) → 플립플롭(기억) → 가산기·해독기·레지스터 → ALU·제어장치·메모리 순으로 쌓임
  - 게이트는 기억이 없고, 플립플롭은 두 출력을 서로의 입력에 엇갈려 연결(교차연결)해 상태를 스스로 유지
  - 0과 1은 전압의 높고 낮음을 해석한 약속
- 전기 기초 (진공관 이해용)
  - 전압 = 전자에 가하는 힘, 전류 = 1초에 지나가는 전자 수, 전력 = 전압 × 전류
  - 전원은 전자를 -쪽으로 밀어 넣어 전위차를 만들고 전자를 순환시킴
  - 저항기 R은 진공관 밖의 별도 부품. 전류를 전압의 높고 낮음(출력 신호)으로 바꿈 (V = I × R)
- CPU와 메모리
  - CPU = ALU + FPU + 레지스터 + 제어장치 (+ 캐시, 코어 여러 개)
  - 명령 실행 : 가져오기(주소선·데이터선) → 해독 → 실행을 반복. 명령도 비트 패턴
  - SRAM : 플립플롭 방식, 트랜지스터 6개 (반전기 2개 × 2 + 읽고 쓰는 문 2개)
  - DRAM : 트랜지스터 1개 + 축전기 1개, 전자가 새서 리프레시 필요
  - 읽기/쓰기는 셀이 아니라 바깥 제어 회로가 구분 (쓰기 구동기가 강하게 밀면 쓰기, 감지 증폭기가 엿보면 읽기)
- 코드가 CPU까지 가는 과정
  - 기계어(CPU마다 다름) → 어셈블리 → 고급 언어. 번역 방식은 컴파일러 / 인터프리터
  - 프로그램 내장 방식(EDSAC, 1949)부터 프로그램이 프로그램을 번역할 수 있게 되어 어셈블러, 컴파일러, OS, JVM이 생김
  - Java : javac → 바이트코드(.class) → JVM(인터프리터 + JIT) → 기계어 → CPU
  - 바이트코드는 파일 안에서 숫자(`c = a + b;` → `1B 1C 60 3E`), `iload_1` 같은 이름은 사람이 읽도록 붙인 니모닉(`javap -c`로 확인)
  - JVM : 클래스 로더, 메서드 영역·힙·스택, GC, OS에는 시스템 호출로 부탁
- 개발 도구
  - IDE : 편집, 자동완성, 실행 버튼. 뒤에서 빌드 도구·javac·java를 호출함. JDK가 없으면 컴파일·실행 불가
  - 빌드 도구(Gradle, Maven) : 라이브러리 내려받아 연결, javac 호출, 테스트, JAR 포장. `src/main/java` 같은 폴더 구조는 관례
  - javac, java, jar는 JDK가 제공하고 빌드 도구는 이를 대신 호출. JAR는 자바 자체의 형식
  - 프레임워크 vs 라이브러리 : 누가 흐름을 쥐고 있나 (프레임워크가 내 코드를 호출 = 제어의 역전)
- 흐름 비교
  - ENIAC : 케이블 배선, 스위치 → 실행
  - 프로그램 내장 초기 : 기계어 직접 작성 → 메모리에 입력 → CPU
  - 어셈블리 : 어셈블리어 → 어셈블러 → 로드 → CPU
  - 컴파일러 : 고급 언어 → 컴파일러 → OS가 로드 → CPU
  - 초기 자바 : 편집기 → javac → java(JVM) → CPU
  - 현대 : IDE → 프로젝트 준비(빌드 도구, 라이브러리, 프레임워크) → 코드 작성 → 빌드 → JVM → CPU

## 머리 정리
> 자료를 닫고, 처음부터 끝까지 내 말로 순서대로 쓰기. 모르는 곳은 (?)로 그대로 남기기.

1. 내가 작성하는 코드는 컴퓨터가 대충 그냥 0과 1로 번역된걸 봐서 뭐 대충 하겠지 라는 안일한 방식의 공부로 인해 컴퓨터가 어떻게 동작하는지도 몰랐던 상태였지만 이번 공부를 통해 감을 잡을 수 있었음
2. 기본적인 0과 1로 구성되며 심지어 CPU를 구성하는 ALU, 제어유닛, 레지스터등이 트랜지스터의 모음이라것을 공부하면서 조금더 컴퓨터를 잘 이해할 수 있게되었음
3. 그에 따라 코드를 작성하고 실행하는 구조를 공부하였고 빌드도구, 라이브러리, 프레임워크가 왜 필요한지, 내가 이를 생략함에 따라 얻을 수 있는 이득이 뭔지, 왜 사용하는지와 같은 근본적인 이유에 대해 생각해보며 내 자바 코드가 어떻게 작동하는지에 대해 깊게 생각해보고 이에 대한 이해가 높아졌음

> [!success]- Q. 그리드 전압이 음극보다 낮으면 왜 닫히나?
> 낮다는 건 그리드가 음극보다 더 -라는 뜻이고, 전자도 -라서 서로 밀어낸다. 그래서 전자가 지나가지 못하고 되돌아간다. 음극과 비슷하면 양극이 당기는 힘으로 지나간다.

> [!success]- Q. 진공관 안에는 저항이 없다면서 왜 회로에 R이 있나?
> R은 진공관 안이 아니라 회로에 따로 단 저항기다. 진공 속에서는 전자가 부딪힐 게 없어서 손실이 없고, R은 전류를 전압 신호로 바꾸려고 일부러 넣은 부품이다.

> [!success]- Q. SRAM은 왜 트랜지스터가 6개나 필요한가?
> 현대 반전기가 트랜지스터 2개 짝(진공관 시절은 진공관 1개 + 저항기)이라서 반전기 2개면 4개이고, 안쪽 두 지점을 바깥 데이터선에 연결하는 문이 2개라서 합쳐 6개다.

> [!success]- Q. 바이트코드는 파일에 iload_1처럼 적혀 있나?
> 아니다. 파일 안에는 숫자만 있고(`1B` = `iload_1`) 이름은 사람이 읽도록 붙인 니모닉이다. `javap -c`가 숫자를 이름으로 바꿔 보여 준다.

> [!success]- Q. 빌드 도구가 컴파일과 JAR 만들기를 제공하는 건가?
> 아니다. javac, java, jar는 JDK의 기능이고 빌드 도구는 이를 알맞은 인자와 순서로 대신 호출한다. 외부 라이브러리는 저장소에서 내려받아 연결해 준다.

> [!success]- Q. ENIAC은 0과 1을 썼나?
> 아니다. ENIAC은 십진수 방식이었고 프로그램은 케이블과 스위치로 짰다. 0과 1(이진수)로 프로그램을 메모리에 넣는 방식은 프로그램 내장 컴퓨터(EDSAC 등)부터다. 코어 로프 메모리는 1960년대 아폴로 컴퓨터다.
