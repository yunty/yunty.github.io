# HTTP 학습 길잡이

이 자료는 **네트워크에서 데이터가 전달되는 과정부터 HTTP API·쿠키·캐시까지 혼자 공부하는 교재**다. 공개된 강의의 주제 순서를 참고했으며, 설명·예시·문제는 별도로 작성했다. 강의 영상이나 유료 수업자료를 열람해 옮긴 자료가 아니다.

## 어떻게 읽을까?

1. 단원의 첫 질문을 보고 자신의 답을 먼저 떠올린다.
2. 본문과 텍스트 그림을 읽고, 예시를 자신의 말로 설명한다.
3. 마지막 확인 문제에 답한다. 답은 [[10_복습 문제 해설]]에 있다.
4. [[09_실습과 종합 과제]]에서 실제 요청·응답을 관찰한다.

모든 그림은 일반 텍스트다. Mermaid 플러그인이나 별도 렌더링 설정 없이 읽을 수 있다. 단원 간 링크는 옵시디언 내부 링크다.

## 먼저 보는 전체 지도

```text
사용자 내부망                  통신사 망                     서비스 망
PC → 공유기 → ONT → 광분배기 → OLT → 집선망·가입자 관리 → 백본 → 목적지 서버
 │                                                         │
 └──────────────────── HTTP 요청과 응답 ──────────────────────┘
```

위의 ONT·광분배기·OLT는 FTTH·PON의 한 예다. 다른 가입자망에서는 장비가 달라진다. **HTTP는 이 경로 자체를 만드는 규약이 아니라, 그 경로를 통해 프로그램끼리 주고받는 요청·응답의 규약**이다.

```text
애플리케이션: HTTP / API / 웹 로그인 상태
보안:         TLS — HTTPS 통신 보호
전송:         TCP 또는 QUIC — QUIC은 UDP 위에서 동작
네트워크:     IP — 목적지 네트워크로 전달
링크·물리:    이더넷·Wi-Fi·광회선 등
```

## 예시를 읽는 규칙

- 도메인은 `example.com`, 외부 IP는 문서용 주소를 사용한다. 실제로 접속할 서비스가 아니다.
- 직접 실행할 실습 주소는 `http://127.0.0.1:8765`다.
- HTTP 텍스트 예시는 특별한 표시가 없으면 HTTP/1.1 형식이다. 설명용 예시에서는 일부 헤더를 생략한다. 실제 메시지의 길이·경계는 HTTP 라이브러리가 올바르게 처리해야 한다.
- `HTTP 요청 하나 = TCP 패킷 하나`는 아니다. 요청이 여러 조각으로 전송되거나 한 연결에서 여러 요청이 처리될 수 있다.
- 웹의 ‘세션’과 TCP의 ‘연결 상태’는 다른 개념이다. 두 개를 항상 구분한다.

## 학습 출발점

다음 질문에 막히면 해당 단원을 다시 읽는다.

- IP가 있는데 MAC과 포트가 왜 필요한가? → 1단원
- 주소창에 URL을 넣으면 어떤 순서로 처리되는가? → 2단원
- HTTP는 무상태인데 로그인은 어떻게 유지되는가? → 3·7단원
- 주문 요청의 응답이 끊어졌다면 다시 보내도 되는가? → 4·5단원
- 저장된 응답을 언제 다시 써도 되는가? → 8단원
