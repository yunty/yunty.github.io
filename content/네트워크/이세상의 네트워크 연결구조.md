# 인터넷과 건물 네트워크의 전체 구조

## 1. 전체 연결 구조

인터넷은 **사용자 장비 → 가입자망 → 통신사 집선망 → 통신사 백본망 → 목적지 네트워크**로 이어진다.

집까지 PON 광회선이 들어오는 대표적인 구성은 다음과 같다. 모든 연결은 양방향이다.

```
[PC·휴대폰]
     ↕ 랜선·Wi-Fi
  [공유기]
     ↕ 이더넷
 [ONU·ONT]
     ↕ 광케이블
  [광분배기]
     ↕ 광케이블
[국사 내 OLT]
     ↕ 이더넷 업링크 — 주로 광 연결
 [지역 집선망]
     ↕
[가입자 접속 관리 장비 — BNG 등]
     ↕
[통신사 백본망]
     ↕
[목적지 사업자 망]
     ↕
 [목적지 서버]
```

> [!important] 실제 구성은 달라질 수 있다  
> 위 그림은 대표적인 논리 구조다. BNG의 위치, 집선 단계 수, 장비의 통합 여부는 통신사에 따라 다르다. 목적지 서버가 가입한 통신사 망에 직접 연결되어 있다면 다른 통신사 망을 거칠 필요도 없다.

전체 구조를 구간별로 나누면 다음과 같다.

|구간|범위|주요 역할|
|---|---|---|
|사용자 내부망|PC·휴대폰 ↔ 공유기·내부 스위치|내부 장비 연결|
|가입자망, 액세스망|가입자 위치 ↔ 통신사 수용 장비|개별 가입자를 통신사 망에 연결|
|집선망|여러 액세스 장비 ↔ 상위 거점|많은 가입자의 트래픽을 모아 전달|
|백본망, 코어망|통신사의 주요 거점 사이|지역 간 대용량 트래픽 전달|
|망 간 연결|통신사 ↔ 다른 통신사·콘텐츠 사업자|서로 다른 사업자 망 사이의 통신|
|목적지 네트워크|데이터센터·회사·다른 사용자망 등|실제 통신 대상에 도달|

## 2. 가입자망: 집·건물에서 통신사까지

### 2.1 ONU와 ONT

**ONU는 가입자 쪽에서 PON 광회선을 끝내고 이더넷 등의 연결을 제공하는 장비**다.

OLT와 PON 방식으로 통신하며, 양방향 데이터를 전달한다.

**ONT는 최종 가입자 위치에 설치되는 ONU를 가리키는 명칭**이다. 제조사와 통신사에 따라 두 용어를 비슷하게 사용하기도 한다.

|장비|의미|대표적인 위치|
|---|---|---|
|ONU|가입자 측 PON 종단 장비를 넓게 지칭|건물 통신실, 가입자 위치 등|
|ONT|최종 가입자 위치의 ONU를 지칭|집·사무실|

```
FTTH의 한 예
통신사 OLT ↔ 광분배기 ↔ 집 ONT ↔ 공유기 ↔ PC

FTTB에서 PON을 사용하는 예
통신사 OLT ↔ 광분배기 ↔ 건물 ONU ↔ 내부 배선·스위치 ↔ 각 세대
```

ONT와 공유기는 별도 장비일 수도 있고, 일체형일 수도 있다.

### 2.2 광분배기

**광분배기(Optical Splitter)는 광신호를 여러 갈래로 나누거나 합치는 수동 장치**다.

```
                        ┌─ ONT A
OLT ── 광섬유 ── 광분배기 ┼─ ONT B
                        └─ ONT C
```

- 전원이 필요 없다.
    
- MAC이나 IP 주소를 읽어 목적지를 판단하지 않는다.
    
- 하향 신호는 연결된 여러 ONT 쪽으로 분배된다.
    
- 상향 신호는 OLT 방향으로 합쳐진다.
    
- 빛을 나눌수록 각 경로의 광신호 세기가 줄어든다.
    

여러 ONT가 상향으로 동시에 보내면 신호가 겹칠 수 있으므로, 일반적인 GPON·XGS-PON에서는 **OLT가 ONT별 전송 시간을 조율**한다.

### 2.3 OLT

**OLT는 통신사 쪽에서 PON을 운영하는 장비**다.

주요 기능은 다음과 같다.

- 연결된 ONU·ONT를 식별하고 등록을 허용한다.
    
- 상향 전송 시간을 배정하고 대역폭을 관리한다.
    
- 가입자 쪽 PON과 상위 이더넷 망 사이에서 데이터를 전달한다.
    
- 서비스에 필요한 VLAN·속도 등의 설정을 적용한다.
    

```
가입자 쪽                               통신사 상위 망
ONU·ONT들 ↔ 광분배기 ↔ [PON 포트 | OLT | 업링크 포트] ↔ 집선 장비
```

|OLT의 포트|역할|
|---|---|
|PON 포트|광분배기를 거쳐 ONU·ONT들과 연결|
|업링크 포트|집선 스위치·라우터 등 상위 장비와 연결|
|관리 포트|관리망을 통한 설정·상태 확인|
|콘솔 포트|장비에 직접 접속해 설정·점검|

> [!note] 광포트가 있다고 모두 OLT는 아니다  
> 일반 이더넷 스위치에도 광포트가 있다. OLT는 **PON 프로토콜로 ONU·ONT를 관리하는 기능**으로 구분한다. 광 이더넷 포트와 PON 포트는 통신 방식이 다르다.

### 2.4 국사

**국사는 통신 장비를 설치하고 운영하는 건물·시설**이다.

국사 안에는 역할에 따라 다음 장비가 들어갈 수 있다.

- OLT와 가입자 수용 스위치
    
- 집선 스위치·라우터
    
- 백본 라우터
    
- 광전송 장비
    
- 전원·배터리·냉각 설비
    

**국사는 장소이고, OLT는 그 안에 설치될 수 있는 장비**다. 모든 국사가 같은 장비와 역할을 갖는 것은 아니다.

## 3. FTTH·FTTB와 PON·AON

이 용어들은 서로 다른 기준으로 망을 분류한다.

- **FTTH·FTTB:** 광케이블이 어디까지 들어오는가?
    
- **PON·AON:** 가입자 연결을 어떤 방식으로 구성하는가?
    

### 3.1 FTTH와 FTTB

|구분|FTTH|FTTB|
|---|---|---|
|의미|Fiber To The Home|Fiber To The Building|
|광케이블 종점|개별 가정|건물|
|건물 내부 연결|집까지 광케이블|랜선·전화선 등 다른 매체 사용 가능|
|대표 구성|집의 ONT → 공유기|건물 장비 → 내부 배선 → 세대|

```
FTTH
통신사 장비 ── 광케이블 ── 집의 광회선 종단 장비 ── 공유기

FTTB
통신사 장비 ── 광케이블 ── 건물 통신실 장비 ── 랜선 등 ── 각 세대
```

FTTH라고 무조건 FTTB보다 빠른 것은 아니다. 실제 성능은 장비, 배선, 가입 상품과 공유 구간의 용량에 따라 달라진다.

### 3.2 PON과 AON

**PON은 전원 없는 광분배기로 회선을 나누는 구조**, **AON은 능동형 이더넷 장비 등을 사용하는 구조**다.

AON도 광케이블을 사용한다.

|구분|PON|AON — Active Ethernet 기준|
|---|---|---|
|대표 연결|OLT ↔ 광분배기 ↔ ONT들|이더넷 스위치 ↔ 가입자별 링크|
|중간 분배 방식|빛을 수동으로 분배|장비가 데이터를 처리해 전달|
|용량 구조|같은 PON 구간의 용량을 가입자들이 공유|가입자별 링크를 구성하고 상위 회선은 공유 가능|
|장점|광섬유·포트 절감, 중간 전원 관리 부담 감소|가입자별 링크 관리·증설에 유리|
|고려 사항|분배 수·거리·광손실·공유 용량|포트·광모듈·전원·장비 관리|

AON의 스위치를 반드시 동네 중간에 설치해야 하는 것은 아니다. 국사에 두고 가입자까지 광섬유를 개별 연결할 수도 있다.

FTTH와 PON은 같은 뜻이 아니다. **FTTH + PON, FTTH + AON, FTTB + PON, FTTB + AON** 등의 조합이 가능하다.

## 4. 집선망·백본망·망 간 연결

### 4.1 집선망

**집선망은 여러 하위 장비의 트래픽을 모아 상위 망으로 전달하는 구간**이다.

```
OLT A ──┐
OLT B ──┼── 집선 스위치·라우터 ── 상위 망
OLT C ──┘
```

- 여러 OLT·가입자 수용 스위치 등을 연결한다.
    
- 하위 회선들을 더 큰 용량의 상위 회선으로 모은다.
    
- VLAN, 라우팅, 트래픽 제어 등을 수행할 수 있다.
    
- 지역에 따라 여러 단계로 구성될 수 있다.
    

집선망은 단일 장비 이름이 아니라 **장비와 연결 회선이 맡는 역할**이다.

### 4.2 BNG와 가입자 관리

**BNG(Broadband Network Gateway)는 통신사의 가입자 접속을 관리하는 장비**다.

통신사 구성에 따라 다음 기능을 수행한다.

- 가입자 세션 식별·관리
    
- AAA 시스템과 연동한 인증·권한 확인
    
- IP 주소 할당 또는 할당 과정 연동
    
- 속도·접속 정책 적용
    
- 가입자 트래픽의 상위 망 전달
    

|구분|확인·관리하는 대상|
|---|---|
|OLT의 ONT 인증|PON에 연결할 장비가 허용된 장비인지|
|BNG·AAA의 가입자 관리|어떤 가입자·회선이며 어떤 서비스를 허용할지|

장비 등록, 가입자 인증, IP 할당은 서로 관련되지만 같은 절차는 아니다.

### 4.3 백본 네트워크

**백본은 여러 하위 네트워크를 연결하는 중심망**이다.

- 건물 백본: 각 층·부서를 연결하는 중심망
    
- 캠퍼스 백본: 여러 건물을 연결하는 중심망
    
- 통신사 백본: 여러 지역 거점을 연결하는 중심망
    

통신사 백본은 여러 거점의 라우터와 광전송 장비, 대용량 회선 등으로 구성된다. 장애 시 우회할 수 있도록 여러 경로로 구성하는 것이 일반적이다.

### 4.4 백본 스위치

**백본 스위치는 중심망에서 트래픽을 전달하는 역할의 스위치**다.

|용어|의미|
|---|---|
|백본 네트워크|중심 장비와 회선으로 구성된 망 전체|
|백본 스위치|중심망을 구성하는 개별 스위치|
|백본 라우터|중심망에서 IP 라우팅을 담당하는 라우터|

‘백본’은 L2·L3처럼 계층을 뜻하지 않는다. **네트워크 안에서 차지하는 역할과 위치**를 뜻한다.

### 4.5 다른 사업자 망과의 연결

인터넷은 여러 사업자가 운영하는 망이 연결된 구조다.

- **피어링:** 망 사이의 합의에 따라 트래픽을 교환
    
- **트랜짓:** 다른 사업자를 통해 더 넓은 인터넷으로 연결
    
- **IX:** 여러 망이 상호 연결할 수 있는 교환 기반 시설
    

모든 트래픽이 한 중앙 IX나 한 국사를 통과하는 것은 아니다. 목적지와 망의 연결 정책에 따라 경로가 달라진다.

## 5. 건물 내부망과 장비의 역할

건물 전체가 하나의 인터넷 계약을 공유하는 대표적인 예다.

```
	        [통신사 회선]
                ↕
	       [회선 종단 장비]
	       PON이면 ONU·ONT
                ↕
	       [라우터·방화벽]
	        필요하면 NAT
                ↕
	       [건물 백본 스위치]
	       필요하면 L3 라우팅
                ↕
      ┌─────────┼─────────┐
      ↕         ↕         ↕
 [1층 스위치] [2층 스위치] [3층 스위치]
      ↕         ↕         ↕
   PC·AP     PC·프린터   PC·카메라
```

일반 광 이더넷 회선은 적합한 광포트를 가진 라우터·스위치에 직접 연결할 수도 있다.

|장비·역할|담당하는 일|
|---|---|
|라우터|서로 다른 IP 네트워크 사이의 경로 선택·전달|
|방화벽|허용할 통신과 차단할 통신 결정|
|백본·코어 스위치|내부 중심에서 여러 하위 연결 처리|
|집선·분배 스위치|여러 액세스 스위치를 모아 연결|
|액세스 스위치|PC·AP 등 최종 장비 연결|
|무선 AP|무선 기기를 내부망에 연결|
|가정용 공유기|보통 라우터·NAT·방화벽·LAN 스위치·AP 기능을 통합|

작은 망에서는 여러 역할을 한 장비가 겸할 수 있다.

각 층을 라우터에 직접 연결해도 된다. 규모가 커지면 포트 수, 처리 용량, 내부 통신과 장애 관리 등을 위해 백본 스위치를 별도로 둔다.

## 6. L1·L2·L3와 스위치·라우터

### 6.1 계층별 역할

|계층|다루는 것|주요 기준·요소|관련 장비|
|---|---|---|---|
|L1: 물리 계층|전기·빛·무선으로 비트 전달|케이블, 파장, 신호|광모듈, 물리 매체 등|
|L2: 데이터링크 계층|같은 링크·VLAN 안에서 프레임 전달|이더넷에서는 MAC 주소|L2 스위치|
|L3: 네트워크 계층|서로 다른 IP 네트워크 사이로 패킷 전달|IP 주소와 라우팅 테이블|라우터, L3 스위치|

L2·L3 장비도 실제 전송을 위해 L1 기능을 사용한다. L3 장비 역시 이더넷 구간에서는 MAC 주소를 사용한다.

### 6.2 L2 스위치

**목적지 MAC 주소를 보고 프레임을 전달할 포트를 결정**한다.

스위치는 들어오는 프레임의 출발지 MAC을 보고 다음과 같은 표를 학습한다.

|VLAN|MAC 주소|연결 포트|
|---|---|---|
|10|PC A의 MAC|1번|
|10|PC B의 MAC|2번|
|20|PC C의 MAC|3번|

목적지 MAC의 위치를 모르면 해당 VLAN의 다른 포트들로 전파할 수 있다.

### 6.3 라우터와 L3 스위치

둘 다 **목적지 IP와 라우팅 테이블을 기준으로 다음 경로를 선택**할 수 있다.

|장비|일반적인 사용|
|---|---|
|라우터|내부망과 외부망 연결, WAN 연결 등|
|L3 스위치|고속 내부 스위칭과 VLAN·서브넷 사이 라우팅|

기능은 제품마다 다르다. NAT·VPN·방화벽 등은 ‘L3’라는 이름만으로 지원 여부를 판단할 수 없다.

### 6.4 스위치를 분류하는 다른 기준

다음 분류는 서로 중복될 수 있다.

|분류 기준|종류|차이|
|---|---|---|
|관리 기능|비관리형 / 관리형|VLAN·포트 제어·상태 확인 등 설정 가능 여부|
|전력 공급|일반 / PoE|랜선으로 AP·카메라 등에 전력 공급 가능 여부|
|연결 매체|구리 / 광 / 혼합형|RJ45, SFP·SFP+ 등 지원 포트|
|배치 역할|액세스 / 집선 / 코어|망에서 맡는 위치와 역할|
|계층 기능|L2 / L3|IP 라우팅 지원 여부|

예를 들어 **‘광 업링크와 PoE를 지원하는 관리형 L2 액세스 스위치’**라는 설명이 가능하다.

## 7. IP·서브넷·VLAN·게이트웨이

### 7.1 IP와 서브넷

**IP 주소와 서브넷 마스크를 함께 봐야 같은 IP 네트워크인지 판단할 수 있다.**

```
192.168.1.10/24
192.168.1.20/24
```

두 주소는 `192.168.1.0/24`에 속한다.

`/24`는 네트워크를 구분하는 부분이 앞의 24비트라는 뜻이고, 마스크로 쓰면 `255.255.255.0`이다.

|네트워크|네트워크 주소|일반적으로 장비에 할당 가능한 주소|브로드캐스트|
|---|---|---|---|
|`192.168.1.0/24`|`192.168.1.0`|`192.168.1.1`~`192.168.1.254`|`192.168.1.255`|

끝이 `.0`, `.255`인 주소의 사용 가능 여부는 **서브넷 크기에 따라 달라진다**. 위 제한은 `/24` 예시다.

### 7.2 VLAN

**VLAN은 스위치 연결을 논리적으로 나누는 L2 통신 구역**이다.

일반적인 설계에서는 VLAN 하나에 IP 서브넷 하나를 대응시킨다.

|구역|VLAN|IP 서브넷|게이트웨이 예시|
|---|---|---|---|
|1층|10|`192.168.1.0/24`|`192.168.1.1`|
|2층|20|`192.168.2.0/24`|`192.168.2.1`|
|방문객|30|`192.168.30.0/24`|`192.168.30.1`|

VLAN과 서브넷은 다른 개념이다.

- VLAN: **L2에서 연결 구역을 분리**
    
- 서브넷: **L3에서 IP 주소 범위를 구분**
    

주소만 다르게 설정한다고 VLAN까지 자동으로 나뉘지는 않는다.

### 7.3 서브넷을 설정하는 장비

관리자가 주소 계획을 정하고 다음 장비에 반영한다.

- 스위치: VLAN과 포트 구성
    
- 라우터·L3 스위치: 각 서브넷의 게이트웨이 인터페이스와 경로
    
- DHCP 서버·단말: IP·마스크·게이트웨이 설정
    

```
[L3 스위치]
  ├─ VLAN 10 인터페이스: 192.168.1.1/24
  └─ VLAN 20 인터페이스: 192.168.2.1/24
```

이 L3 스위치가 두 네트워크 사이를 라우팅할 수 있다. 방화벽·접근 제어 정책에 따라 통신을 제한할 수도 있다.

### 7.4 기본 게이트웨이

**단말이 다른 네트워크로 보낼 때 사용하는 기본 출구**다.

```
PC 주소:       192.168.1.10/24
기본 게이트웨이: 192.168.1.1
```

게이트웨이는 같은 서브넷에 있는 라우터·L3 스위치의 인터페이스 주소 등으로 설정한다.

### 7.5 DHCP

**단말에 네트워크 설정을 자동 배포하는 기능**이다.

주요 배포 정보는 IP 주소, 서브넷 마스크, 기본 게이트웨이, DNS 서버다.

DHCP 서버는 공유기, 서버 또는 지원하는 네트워크 장비에서 운영할 수 있다. DHCP는 주소를 할당하는 기능이며 NAT·라우팅과는 별개다.

## 8. IP와 MAC을 함께 사용하는 이유

**IP는 최종 목적지와 경로를 판단하는 데, MAC은 현재 이더넷 구간에서 다음 장비로 전달하는 데 사용한다.**

```
이더넷 프레임
┌─────────────────────────────────────┐
│ 출발지 MAC · 목적지 MAC                │
│  ┌────────────────────────────────┐ │
│  │ IP 패킷: 출발지 IP · 목적지 IP      │ │
│  │              데이터              │ │
│  └────────────────────────────────┘ │
└─────────────────────────────────────┘
```

### 8.1 같은 서브넷의 PC로 보내기

```
PC A: 192.168.1.10/24
PC B: 192.168.1.20/24
```

1. A가 목적지 IP와 자신의 마스크를 비교한다.
    
2. 같은 서브넷이므로 B에게 직접 전달하기로 한다.
    
3. IPv4에서는 ARP로 B의 MAC 주소를 알아낸다.
    
4. 목적지 IP는 B의 IP, 목적지 MAC은 B의 MAC으로 보낸다.
    
5. L2 스위치가 목적지 MAC을 기준으로 전달한다.
    

같은 VLAN 등 정상적인 L2 연결이 전제다.

### 8.2 다른 서브넷으로 보내기

1. PC가 목적지를 자기 서브넷 밖으로 판단한다.
    
2. 기본 게이트웨이의 MAC 주소를 알아낸다.
    
3. **목적지 IP는 최종 목적지**, **목적지 MAC은 게이트웨이**로 보낸다.
    
4. 라우터가 목적지 IP를 보고 다음 경로를 결정한다.
    
5. 다음 이더넷 구간에 맞는 새 프레임으로 전달한다.
    

라우터를 통과할 때 이더넷 MAC 주소는 구간별로 바뀐다. 출발지·목적지 IP는 NAT 등의 주소 변환이 없다면 일반적으로 유지된다.

## 9. 공인 IP·사설 IP·NAT와 외부 접속

### 9.1 공인 IP와 사설 IP

|구분|공인 IP|사설 IP|
|---|---|---|
|사용 범위|공용 인터넷에서 라우팅하는 주소|내부망에서 사용하는 주소|
|할당|통신사 등에서 정식으로 할당|관리자가 지정된 사설 범위 안에서 설계|
|중복|공용 인터넷에서 충돌하지 않게 관리|분리된 내부망끼리는 중복 가능|

IPv4 사설 주소 범위:

|표기|범위|
|---|---|
|`10.0.0.0/8`|`10.0.0.0`~`10.255.255.255`|
|`172.16.0.0/12`|`172.16.0.0`~`172.31.255.255`|
|`192.168.0.0/16`|`192.168.0.0`~`192.168.255.255`|

서로 다른 집에서 같은 `192.168.0.10`을 사용해도 된다. 다만 두 망을 VPN 등으로 연결할 때는 주소 중복이 문제가 될 수 있다.

### 9.2 NAT

**NAT는 통과하는 패킷의 IP 주소를 변환하는 기능**이다.

가정에서는 보통 포트 번호까지 변환하는 NAPT·PAT 방식으로 공인 IP 하나를 여러 장비가 공유한다.

```
PC A: 사설 IP A ─┐
                ├─ 라우터의 NAT ─ 공인 IP 하나 ─ 인터넷
PC B: 사설 IP B ─┘
```

라우터는 내부 주소·포트와 외부 주소·포트의 대응 관계를 기록한다. 응답이 돌아오면 그 기록에 따라 원래 내부 장비로 전달한다.

사설 IP로 내부 통신만 할 때는 NAT가 필요 없다. 일반적인 IPv4 인터넷과 통신하려면 경로 어딘가에서 주소 변환 등이 필요하다.

### 9.3 NAT 없이 인터넷에 연결하기

할당받은 공인 IP를 내부 장비에 사용하고, 상위 망에 돌아오는 경로가 구성되어 있다면 NAT 없이 통신할 수 있다.

**회선 하나에 공인 IP 여러 개를 라우팅할 수 있다.** 회선 수와 IP 개수는 같은 개념이 아니다.

### 9.4 외부에서 내부 서버로 접속하기

외부에서 새 연결을 시작할 때는 접속 가능한 공인 IP와 내부 서비스까지의 전달 설정이 필요하다.

```
외부 사용자
    ↓ 공인 IP의 TCP 443번 포트
라우터
    ↓ 포트 포워딩
내부 웹서버: 192.168.1.10의 TCP 443번 포트
```

- 포트 포워딩: 외부 주소·포트를 특정 내부 주소·포트로 전달
    
- 방화벽: 해당 접속을 허용할지 결정
    
- DNS: 도메인을 접속할 IP로 알려 줌
    

통신사 NAT 뒤에 있는 경우에는 건물 공유기의 포트 포워딩만으로 외부 접속이 되지 않을 수 있다. IPv6에서는 일반적으로 NAT보다 주소 라우팅과 방화벽 정책을 중심으로 구성한다.

## 10. 서버·데이터센터와 통신망의 관계

**서버는 요청을 처리하는 컴퓨터·프로그램이고, 데이터센터는 서버를 운영하는 시설**이다.

```
사용자 장비 ↔ 사용자 측 망 ↔ 인터넷 ↔ 서비스 측 망 ↔ 서버
```

|구분|역할|
|---|---|
|웹서버|HTTP 요청에 응답하고 웹페이지·파일 등 제공|
|애플리케이션 서버|로그인·주문·게임 등 서비스 로직 처리|
|데이터베이스 서버|서비스 데이터 저장·조회|
|콘텐츠·캐시 서버|영상·이미지·파일 등을 제공|
|데이터센터|전력·냉각·통신망·보안·운영 공간 제공|

서비스 기업은 직접 시설을 구축하거나, 데이터센터 공간을 빌리거나, 클라우드를 사용한다.

데이터센터는 인터넷의 필수 중간 통과 지점이 아니다. **접속하려는 서비스의 서버가 위치하는 장소**이며, 서버 역시 네트워크에 연결된 통신의 한쪽 끝이다.

## 11. 실제 통신 흐름으로 연결해서 보기

건물의 PC가 외부 웹사이트에 접속하는 예다.

```
PC
 ↕
층별 L2 스위치
 ↕
L3 백본 스위치
 ↕
외부 연결 라우터·방화벽·NAT
 ↕
ONU·ONT — PON 회선일 때
 ↕
광분배기
 ↕
통신사 OLT
 ↕
통신사 집선망·가입자 관리 장비
 ↕
통신사 백본망
 ↕
목적지 사업자 망
 ↕
웹서버
```

처리 순서:

1. **주소 확인:** DNS 등을 통해 웹사이트의 접속 IP를 얻는다.
    
2. **목적지 판단:** PC가 IP와 마스크를 비교해 외부 목적지임을 판단한다.
    
3. **내부 전달:** 게이트웨이 MAC을 목적지로 한 프레임을 L2 스위치를 통해 보낸다.
    
4. **라우팅:** L3 장비가 목적지 IP에 맞는 경로로 전달한다.
    
5. **주소 변환:** 구성에 따라 경계 라우터가 사설 IP·포트를 변환한다.
    
6. **가입자망 통과:** PON이라면 ONT·광분배기·OLT를 거친다.
    
7. **통신사 망 통과:** 집선망과 백본을 통해 목적지 망으로 전달된다.
    
8. **서버 처리:** 서버가 요청을 처리하고 응답을 보낸다.
    
9. **응답 전달:** 라우팅과 NAT 연결 기록 등에 따라 PC로 돌아온다.
    

응답은 같은 장비·회선을 정확히 역순으로 지나간다고 보장되지는 않는다. 인터넷에서는 방향에 따라 경로가 달라질 수 있다.

> [!summary] 개념을 구분하는 기준
> 
> - **FTTH·FTTB:** 광케이블이 어디까지 오는가?
>     
> - **PON·AON:** 가입자 연결을 어떤 방식으로 구성하는가?
>     
> - **ONU·ONT·OLT:** PON의 양 끝에서 어떤 역할을 하는가?
>     
> - **국사·데이터센터:** 장비를 설치하는 장소는 어디인가?
>     
> - **액세스·집선·백본:** 망 안에서 어떤 위치와 역할을 맡는가?
>     
> - **L2·L3:** 어떤 계층의 정보를 보고 전달하는가?
>     
> - **VLAN·서브넷:** L2 연결 구역과 L3 주소 범위를 어떻게 나누는가?
>     
> - **DHCP·라우팅·NAT:** 설정 배포, 경로 선택, 주소 변환 중 무엇을 하는가?
>
