# http
## 네트워크
### IP
- 지정한 IP주소에 데이터를 전달하는 프로토콜
- 패킷 단위로 전달
#### 단점
- 상대방이 없어도 패킷을 전송
- 전송 보장x
- 순서 보장x

### TCP
TCP 3 way handshake를 통해 신 -> 신액 -> 액으로 연결 상태를 보장 및 순서를 보장해줌

### UDP
IP와 거의 동일하고 뒤에 포트가 붙고 체크섬이 추가되었다

### PORT
동일한 IP에서 프로세스를 구분해준다.

### DNS
도메인 네임 시스템
IP에 이름을 붙여둔것임

## URI
Uniform Resource Identifier이며 URL과 URN으로 분류됨
URI만으로 리소스를 찾을 수 있는 정보가 담겨있음

### URL
Uniform Resource Locator
리소스가 있는 위치를 지정

### URN
Uniforrm Resource Name
리소스에 이름을 부여한다.
현재 보편화된 사용법이 없음

## URL
==scheme://[userinfo@]host[:port][/path][?query][#fragment]==
`https://www.google.com:443/search?q=hello&hl=ko`
프로토콜을 사용해서 호스트 주소와 통신하며 포트로 소켓에 연결하며, 패스와 쿼리로 http요청을 보낸다.
### scheme
프로토콜 : https
### host
호스트명 : `www.google.com`
도메인명 혹은 IP주소
### PORT
포트번호 : 443
https의 포트번호가 443
### PATH
리소스의 경로 /search
디렉토리경로와 비슷
### query
?를 붙여서 시작, &로 여러개 추가 가능
?q=hello&hl=ko

## HTTP
HyperText Transfer Protocol
클라이언트 서버 구조
stateless
비연결성

### stateful
서버가 클라이언트의 상태를 보존하고 있음
장점 : 가벼움
단점 : 확장이 어렵움

### stateless
서버가 클라이언트의 상태를 보존x
장점 : 서버 확장성 높음(스케일 아웃)
단점 : 클라이언트가 추가 데이터 전송

### 비연결성
응답이 오면 TCP연결을 끊음

#### 현재
HTTP 지속 연결을 통해 재사용 후 종료함
