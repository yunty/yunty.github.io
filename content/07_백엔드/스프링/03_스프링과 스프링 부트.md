# 스프링과 스프링 부트

---
## 스프링이란
- 자바로 웹 애플리케이션을 만들 때 쓰는 **프레임워크**
- 핵심은 객체를 **대신 만들고 연결**해주는 것
	- 스프링 컨테이너가 객체(빈)를 관리하고, DI로 서로 연결해줌
- 그 위에 웹(MVC), DB 접근, 트랜잭션, AOP 같은 기능들이 올라가 있음
- 즉 개발자는 **비즈니스 로직에 집중**할 수 있게 해주는 틀

## 스프링 부트란
- 스프링을 **쉽게 시작**하게 해주는 것
- 스프링이 못하던걸 하는게 아니라, 스프링 쓸 때 필요한 **설정을 대신**해줌

---
## 부트가 대신 해주는 것
| 전에는 직접 | 부트가 |
|---|---|
| 톰캣 설치, WAR 배포 | 톰캣 **내장** → jar 실행하면 같이 뜸 |
| 라이브러리 버전 맞추기 | starter, 버전 관리 |
| DispatcherServlet, DataSource 같은 설정 | **자동 설정**. 필요한 빈을 만들어서 등록 |
| 접속 정보 같은 설정 | `application.properties` |

- 직접 해보고 느낀 예) DB 주소만 `application.properties`에 적었는데 `DataSource`가 이미 빈으로 있어서 주입만 받으면 됐음

---
## 구조로 보면
```
jar 실행
 └ 스프링 부트
     ├ 내장 톰캣 (WAS)
     │    └ DispatcherServlet (스프링 MVC)
     └ 스프링 컨테이너
          ├ Controller / Service / Repository (빈)
          └ DataSource (자동 생성)
```

---
## 한 줄 정리
- 스프링 = 프레임워크
- 스프링 부트 = 스프링 + 톰캣 + 자동 설정을 묶어서 바로 돌아가게 한 것
