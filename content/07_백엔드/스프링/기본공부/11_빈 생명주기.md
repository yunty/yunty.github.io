# 빈 생명주기

---
## 흐름
```
스프링 컨테이너 생성 → 객체 생성 → 의존관계 주입 → 초기화 콜백 → 사용 → 소멸 콜백 → 종료
```
| 단계 | 내용 |
|---|---|
| 객체 생성 | 컴포넌트 스캔은 컨테이너가 생성자 호출, `@Bean`은 메서드가 반환한 객체를 받음 |
| 의존관계 주입 | setter, 필드 등으로 채움 |
| 초기화 콜백 | 주입이 **다 끝난 뒤** 스프링이 호출해주는 초기화 메서드 |
| 소멸 콜백 | 컨테이너가 종료되기 **직전**에 호출 (자원 정리) |

- **생성자 주입**이면 객체 생성과 의존관계 주입이 한 번에 끝남 (두 단계가 합쳐진 특수한 경우)
- `@Bean` 메서드 안에서 내가 `new` + `setUrl()` 한 것까지가 "객체 생성" 단계. 컨테이너는 메서드가 반환한 뒤에 초기화 콜백을 호출
- 즉 `new`는 자바의 일이고, 컨테이너가 받아서 초기화까지 마쳐야 쓸 수 있는 빈

---
## 생성과 초기화를 나누는 이유
| | 하는 일 |
|---|---|
| 생성 | 필수 값(파라미터)을 받아서 객체를 만듦. 가볍게 |
| 초기화 | 그 값으로 DB·네트워크 연결 같은 **무거운 준비** |

- 생성자에서 연결까지 하면 값이 들어오기 전에 실행되거나(`url = null`), 연결 실패로 객체 자체가 안 만들어짐
- 필드에 값 넣는 정도로 가벼우면 생성자에서 같이 해도 됨
- 그래서 초기화는 **주입이 끝난 뒤** 시점에 하도록 콜백을 따로 둠

---
## 콜백 지정 방법
| 방법 | 설명 |
|---|---|
| `@PostConstruct`, `@PreDestroy` | 메서드에 붙이면 끝. **가장 권장** |
| `@Bean(initMethod = "init", destroyMethod = "close")` | 설정에서 지정. 외부 라이브러리 클래스에도 쓸 수 있음 |
| `InitializingBean`, `DisposableBean` | 인터페이스 구현. 옛 방식이라 거의 안 씀 |

```java
@PostConstruct
public void init() {
	connect();   // 주입이 끝난 뒤 실행
}

@PreDestroy
public void close() {
	disconnect();   // 종료 직전 실행
}
```

---
## 한 줄 정리
- 생명주기 = 객체 생성 → 의존관계 주입 → 초기화 콜백 → 사용 → 소멸 콜백
- 무거운 초기화는 생성자에서 빼서 초기화 콜백에서, 자원 정리는 소멸 콜백에서
