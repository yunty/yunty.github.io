# 톰캣과 서블릿
톰캣이 서블릿을 어떻게 부르는지, 요청 하나가 들어와서 나가기까지 순서로 보기

---
## 서블릿
- 자바로 HTTP 요청과 응답을 처리하는 표준 방식
- `HttpServlet`을 상속해서 `service(req, resp)`를 구현하는 형태
- 개발자는 HTTP 글자를 직접 해석하지 않고, **톰캣이 만들어준 req, resp 객체**를 사용함

## 톰캣이 하는 일 (서블릿 컨테이너)
1. 소켓으로 연결을 받음. 요청 1개를 스레드 1개가 맡음 (스레드 풀)
2. HTTP 글자를 해석해서 `Request` 객체 생성
3. 비어있는 `Response` 객체 생성
4. URL 패턴으로 **어떤 서블릿**을 부를지 선택
5. 필터를 거쳐서 `service(req, resp)` 호출
6. 끝나면 Response를 HTTP 글자로 바꿔서 소켓으로 전송

```java
// 톰캣 쪽 (줄인 모양)
Socket socket = serverSocket.accept();
Request req = parse(socket.getInputStream());
Response resp = new Response(socket.getOutputStream());

Servlet target = pickByUrlPattern(req.getPath());
new FilterChain(filters, target).doFilter(req, resp);  // → target.service(req, resp)

resp.flush();  // HTTP 응답으로 전송
```
- 여기까지가 톰캣의 일. `service()`가 호출되는 순간부터 내 코드(스프링)가 시작됨

---
## 서블릿 생명주기
| 메서드 | 언제 |
|---|---|
| `init()` | 톰캣이 서블릿을 만든 직후 1번 |
| `service()` | 요청이 올 때마다 |
| `destroy()` | 종료될 때 |

---
## 스프링이랑 이어지는 지점
- 스프링 MVC는 서블릿 **딱 하나(DispatcherServlet)** 가 `/` 패턴으로 모든 요청을 받음
- 즉 톰캣 입장에서는 스프링도 그냥 서블릿 하나
- 이렇게 한 곳에서 요청을 받아서 나눠주는 구조를 프론트 컨트롤러 패턴이라고 함
