# 웹 서버, 프록시, WAS
요청이 들어왔을 때 **누가 어디까지 처리하는지** 구분해보기

---
## 한눈에
```
클라이언트 → 프록시 서버 → 웹 서버 → WAS → DB
```
- 실제로는 프록시와 웹 서버를 한 프로그램이 같이 하는 경우가 많음 ex) Nginx

---
## 웹 서버 (Web Server)
- HTTP 요청을 받아서 **정적 컨텐츠**(HTML, CSS, JS, 이미지)를 그대로 내려줌
- 즉 파일을 찾아서 보내주는 쪽. 코드를 실행하지는 않음
- ex) Nginx, Apache

## WAS (Web Application Server)
- 웹 서버 기능 + **애플리케이션 코드 실행**(동적 컨텐츠)
- 요청에 맞게 자바 코드를 돌려서 결과(HTML, JSON)를 만들어줌
- ex) 톰캣, Jetty, Undertow
- 톰캣은 **서블릿 컨테이너**. 서블릿을 만들고 호출해주는 곳 → [[07_백엔드/스프링/02_톰캣과 서블릿|톰캣과 서블릿]]

## 프록시 서버
- 클라이언트와 서버 **사이에서 대신 전달**해주는 서버

| | 포워드 프록시 | 리버스 프록시 |
|---|---|---|
| 위치 | 클라이언트 쪽 | 서버 쪽 |
| 누구 대신 | 클라이언트 | 서버 |
| 하는 일 | 접근 차단, 캐시, 익명화 | 로드밸런싱, HTTPS 처리, 캐시, 서버 숨김 |

- 내가 본건 주로 **리버스 프록시**. 서버 앞에 두고 요청을 여러 WAS로 나눠줌

---
## 역할 나눠보기
| | 하는 일 | 대표 |
|---|---|---|
| 웹 서버 | 정적 파일 응답 | Nginx, Apache |
| 프록시 | 중간에서 전달, 분산 | Nginx |
| WAS | 코드 실행 → 동적 응답 | 톰캣 |
| 스프링 | WAS 안에서 도는 **내 코드의 틀** | - |
| DB | 데이터 저장 | H2, MySQL |

---
## 헷갈렸던 것
> 웹 서버랑 WAS는 완전히 따로인가?
- 요즘은 WAS(톰캣)도 정적 파일을 줄 수 있어서 경계가 흐려짐
- 그래도 정적은 웹 서버, 동적은 WAS로 나누면 WAS는 코드 실행에만 집중할 수 있음

> 스프링 부트는 왜 톰캣을 따로 설치 안 해도 되나?
- 스프링 부트가 **톰캣을 안에 품고(내장)** 있어서 실행하면 같이 뜸 → [[07_백엔드/스프링/03_스프링과 스프링 부트|스프링과 스프링 부트]]
