# 커밋 메시지 작성법과 예시

이전 페이지: [[05_Git/01_Git 기본 사용법|Git 기본 사용법]]

**커밋 메시지는 이번 변경에서 무엇을 했는지 짧게 설명하는 글이다.** 아래는 AngularJS의 커밋 규칙을 참고한 한글 예시이며, 실제 미션이나 팀에서 정한 규칙이 있으면 그 규칙을 따른다. [AngularJS 커밋 규칙](https://github.com/angular/angular.js/blob/master/DEVELOPERS.md#git-commit-guidelines)

## 1. 기본 형식

```text
타입: 변경 내용
```

```text
feat: 커스텀 구분자 지원
```

- `feat`: 어떤 종류의 변경인지 나타낸다.
- `커스텀 구분자 지원`: 무엇을 바꿨는지 설명한다.
- 콜론 뒤에는 한 칸 띄운다.

변경한 영역을 표시하고 싶다면 `feat(parser): 커스텀 구분자 지원`처럼 쓴다. 괄호 안의 `parser`는 변경 영역을 뜻하며 생략할 수 있다. [Conventional Commits 형식](https://www.conventionalcommits.org/en/v1.0.0/)

## 2. 상황별 타입과 예시

| 타입 | 사용하는 상황 | 커밋 메시지 예시 |
| --- | --- | --- |
| `feat` | 새로운 기능 구현 | `feat: 커스텀 구분자 지원` |
| `fix` | 기존 기능의 오류 수정 | `fix: 빈 문자열 입력 시 0을 반환하도록 수정` |
| `docs` | 문서 작성 또는 수정 | `docs: README에 기능 목록 작성` |
| `refactor` | 동작을 유지하면서 코드 구조 개선 | `refactor: 구분자 추출 로직을 별도 메서드로 분리` |
| `test` | 테스트 추가 또는 수정 | `test: 음수 입력 시 예외가 발생하는 테스트 추가` |
| `style` | 공백·들여쓰기 등 코드 서식 수정 | `style: 들여쓰기와 줄바꿈 정리` |
| `chore` | 개발 설정이나 보조 작업 | `chore: .gitignore에 macOS 임시 파일 패턴 추가` |
| `perf` | 성능 개선 | `perf: 반복문 안의 중복 문자열 분리 제거` |

타입의 기본 의미는 [AngularJS 커밋 규칙](https://github.com/angular/angular.js/blob/master/DEVELOPERS.md#type)을 참고했다.

### 헷갈릴 때 구분하기

- **처음 검증 기능을 구현했다면 `feat`**, 이미 있는 검증이 잘못 동작해서 고쳤다면 `fix`.
- **결과는 그대로이고 코드를 정리했다면 `refactor`**, 공백·줄바꿈만 바꿨다면 `style`.
- 기능 구현과 그 기능의 테스트를 함께 커밋한다면 보통 `feat`. 테스트만 따로 추가한다면 `test`.

`fix`의 빈 문자열 예시는 원래 요구사항이 “빈 문자열은 0을 반환한다”인 경우다. 파일 이름보다 **변경의 목적**으로 타입을 고른다.

## 3. 문자열 덧셈 계산기에서 사용할 예시

아래는 실제로 해당 작업을 했을 때 사용할 수 있는 메시지다. 구현 순서를 강제하는 목록은 아니다.

```text
docs: 문자열 덧셈 계산기 기능 목록 작성
feat: 콘솔에서 계산할 문자열 입력받기
feat: 쉼표와 콜론을 기준으로 숫자 분리
feat: 분리한 숫자의 합 계산
feat: 커스텀 구분자 지원
feat: 잘못된 입력에 IllegalArgumentException 발생
feat: 지정된 형식으로 덧셈 결과 출력
test: 빈 문자열과 복합 구분자 입력 테스트 추가
refactor: 입력 처리와 덧셈 계산 책임 분리
```

## 4. 실제로 입력하는 방법

IntelliJ의 **커밋 메시지 입력란**에는 메시지만 적는다.

```text
feat: 커스텀 구분자 지원
```

터미널에서는 커밋할 변경을 `add`한 뒤 다음처럼 입력한다.

```bash
git commit -m "feat: 커스텀 구분자 지원"
```

설명이 더 필요하면 제목 다음에 빈 줄을 넣고 이유를 적는다.

```text
fix: 빈 문자열 입력 시 0을 반환하도록 수정

빈 문자열을 숫자로 변환하면서 예외가 발생했다.
숫자 변환 전에 빈 문자열을 확인하여 0을 반환한다.
```

## 5. 작성할 때 기억할 것

- `수정`, `완료`처럼 막연하게 쓰기보다 **무엇을 바꿨는지** 적는다.
- 파일 하나마다 나누기보다 **기능 목록의 의미 있는 작업 단위**로 커밋한다.
- 관계없는 변경은 별도 커밋으로 나누고, 메시지는 실제 변경 내용과 맞춘다.
