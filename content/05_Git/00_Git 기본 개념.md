# Git 기본 개념

**Git은 파일의 변경 이력을 기록하고, 이전 버전과 비교하거나 여러 작업을 합칠 수 있게 해주는 도구다.**

예를 들어 `최종.java`, `진짜최종.java`를 계속 만드는 대신, 같은 파일의 변경 과정을 Git에 기록한다.

## 1. Git과 GitHub의 차이

| 이름 | 역할 |
| --- | --- |
| **Git** | 내 컴퓨터에서 파일의 변경 이력을 관리하는 도구 |
| **GitHub** | Git 저장소를 온라인에 보관하고 다른 사람과 협업하는 서비스 |

Git은 GitHub 없이도 사용할 수 있다. GitHub Desktop은 Git 작업을 버튼으로 할 수 있게 해주는 앱이다.

## 2. 파일 수정부터 업로드까지

```text
작업 폴더: 파일 수정
   ↓ add
스테이징 영역: 기록할 내용 선택
   ↓ commit
로컬 저장소: 내 컴퓨터에 버전 기록
   ↓ push
원격 저장소: GitHub에 업로드
```

| 용어 | 의미 |
| --- | --- |
| 작업 폴더(Working Tree) | 내가 실제로 파일을 열고 수정하는 공간 |
| 스테이징 영역(Stage / Index) | 다음 커밋에 넣을 내용을 준비하는 공간 |
| 커밋(Commit) | 선택한 내용을 하나의 버전으로 남기는 기록 |
| 로컬 저장소 | 내 컴퓨터에 있는 Git 저장소 |
| 원격 저장소 | GitHub 등 외부에 있는 Git 저장소 |

**파일 저장 ≠ 커밋 ≠ 업로드**다. 파일을 저장해도 커밋은 생기지 않고, 커밋해도 자동으로 GitHub에 올라가지는 않는다.

`add`한 뒤 파일을 다시 수정했다면, 추가 수정도 커밋에 넣으려면 다시 `add`해야 한다. [공식 기본 안내](https://git-scm.com/docs/gittutorial)

## 3. 자주 만나는 용어

| 용어 | 의미 |
| --- | --- |
| `clone` | 기존 저장소의 파일과 이력을 내 컴퓨터로 복제하기 |
| `fetch` | 원격의 새 이력을 가져오기. 현재 작업 브랜치에 합치지는 않음 |
| `pull` | 원격의 새 이력을 가져와 현재 작업 브랜치에 반영하기 |
| 브랜치(Branch) | 기존 작업에서 갈라져 별도로 작업할 수 있는 흐름 |
| `main` | 주된 작업 흐름에 흔히 붙이는 브랜치 이름 |
| `origin` | 원격 저장소 주소에 흔히 붙이는 별칭 |
| 병합(Merge) | 다른 브랜치의 작업 이력을 현재 브랜치에 합치기 |
| 충돌(Conflict) | 서로 다른 변경을 Git이 자동으로 합치지 못해 직접 정리해야 하는 상황 |

예를 들어 `main`에서 `feature/login` 브랜치를 만들어 로그인 기능을 구현하고, 완성되면 `main`에 병합한다.

`clone`은 처음 가져올 때, `pull`은 이미 가져온 저장소를 업데이트할 때 사용한다. [clone](https://git-scm.com/docs/git-clone), [pull](https://git-scm.com/docs/git-pull)
