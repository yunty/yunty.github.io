# 백엔드 개발자를 위한 터미널 명령어 정리

백엔드 서버는 대부분 화면이 없어서 터미널로 다룹니다. 이 문서는 **처음에 꼭 익혀 둘 명령어**를 용도별로 정리한 것입니다. 맥(zsh) 기준이고, 리눅스 서버와 다른 부분은 따로 표시했습니다.

> 모든 명령을 외울 필요는 없습니다. **자주 쓰는 20~30개와 검색하는 습관**이면 충분합니다.

---

## 0. 명령어를 읽는 법

```
ls -la ~/Documents
│   │   └─ 인자(argument): 명령이 다룰 대상
│   └─ 옵션(option): 동작 방식을 바꿈 (-l, -a 는 -la 로 묶어 쓸 수 있음)
└─ 명령(command)
```

| 개념 | 설명 |
|---|---|
| **프롬프트** | `user@mac ~ %` 같은 입력 대기 표시. 여기에 명령을 입력 |
| **현재 위치** | 명령은 "지금 있는 폴더" 기준으로 동작. `pwd`로 확인 |
| **절대 경로** | `/Users/user/...` 처럼 `/`로 시작. 어디서든 같은 곳 |
| **상대 경로** | `./a.txt`, `../b` 처럼 현재 위치 기준. `.`은 현재, `..`은 상위 폴더 |
| **홈 폴더** | `~` 는 내 홈 폴더(`/Users/내이름`) |

### 모를 때 찾는 법

| 명령 | 설명 |
|---|---|
| `명령 --help` | 간단한 사용법 (예: `curl --help`) |
| `man 명령` | 자세한 설명서. `q`로 종료, `/단어`로 검색 |

### 꼭 알아둘 단축키

| 키 | 동작 |
|---|---|
| `Tab` | 파일·폴더 이름 자동 완성 (오타 방지, 많이 쓰기) |
| `↑` / `↓` | 이전·다음에 쓴 명령 |
| `Ctrl + R` | 지난 명령 검색 |
| `Ctrl + C` | 실행 중인 명령 **중단** |
| `Ctrl + D` | 입력 종료·로그아웃 |
| `Ctrl + L` (또는 `clear`) | 화면 지우기 |
| `Ctrl + A` / `Ctrl + E` | 줄의 맨 앞 / 맨 뒤로 이동 |

## 1. 이동과 둘러보기

### `pwd` — 지금 어디 있는지
```bash
pwd
```
현재 폴더의 절대 경로를 출력합니다.

### `cd` — 폴더 이동
```bash
cd ~/Documents      # 홈의 Documents로
cd ..               # 한 단계 위로
cd -                # 바로 전에 있던 곳으로
cd                  # 홈으로
```

### `ls` — 목록 보기
```bash
ls                  # 이름만
ls -l               # 자세히 (권한, 크기, 날짜)
ls -a               # 숨김 파일(.으로 시작)도 포함
ls -lh              # 크기를 읽기 쉬운 단위(KB, MB)로
ls -lt              # 최근 수정한 순서
```
`-l -a -h`는 `ls -lah`처럼 묶어서 자주 씁니다.

## 2. 파일과 폴더 다루기

### `mkdir` — 폴더 만들기
```bash
mkdir study
mkdir -p a/b/c      # 중간 폴더까지 한 번에 (-p)
```

### `touch` — 빈 파일 만들기 (이미 있으면 수정 시간만 갱신)
```bash
touch memo.txt
```

### `cp` — 복사
```bash
cp a.txt b.txt          # 파일 복사
cp -r src backup        # 폴더는 -r (재귀)
```

### `mv` — 이동 / 이름 바꾸기
```bash
mv a.txt b.txt          # 이름 변경
mv a.txt ~/Documents/   # 이동
```

### `rm` — 삭제 (**휴지통 없이 바로 삭제**)
```bash
rm a.txt
rm -i a.txt             # 지우기 전에 확인
rm -r folder            # 폴더 삭제
```
> ⚠ `rm -rf`는 확인 없이 **되돌릴 수 없게** 지웁니다. 경로를 두 번 확인하고, `rm -rf /` 나 `rm -rf *` 처럼 범위가 큰 명령은 절대 습관처럼 쓰지 마세요.

### 파일 내용 보기

| 명령 | 용도 | 예 |
|---|---|---|
| `cat` | 짧은 파일 전체 출력 | `cat memo.txt` |
| `less` | 긴 파일을 페이지 단위로 (`q` 종료, `/단어` 검색) | `less app.log` |
| `head` | 앞부분 | `head -n 20 app.log` |
| `tail` | 뒷부분 | `tail -n 100 app.log` |
| `tail -f` | **실시간으로 계속 보기** (로그 확인에 필수, `Ctrl+C`로 종료) | `tail -f app.log` |

## 3. 검색과 필터

### `grep` — 글자 찾기
```bash
grep "ERROR" app.log              # 줄에서 ERROR가 포함된 것만
grep -i "error" app.log           # 대소문자 무시
grep -n "ERROR" app.log           # 줄 번호 함께
grep -v "DEBUG" app.log           # DEBUG 가 없는 줄만 (제외)
grep -C 3 "ERROR" app.log         # 앞뒤 3줄도 함께
grep -rn "TODO" src/              # 폴더 안 모든 파일에서 (재귀)
```

### `find` — 파일 찾기
```bash
find . -name "*.log"              # 현재 폴더 아래에서 이름이 .log 로 끝나는 파일
find . -type f -mtime -1          # 최근 하루 안에 수정된 파일
find . -size +100M                # 100MB 보다 큰 파일
```

### 파이프 `|` — 앞 명령의 출력을 다음 명령의 입력으로
```bash
cat app.log | grep ERROR | wc -l  # ERROR 가 몇 줄인지
ps aux | grep java                # 실행 중인 java 프로세스 찾기
```

### 보조 도구

| 명령 | 용도 | 예 |
|---|---|---|
| `wc -l` | 줄 수 세기 | `wc -l app.log` |
| `sort` | 정렬 | `sort names.txt` |
| `uniq -c` | 연속된 중복을 세어 합침 (보통 `sort` 뒤에) | `sort ips.txt \| uniq -c` |
| `echo` | 글자 출력 | `echo hello` |

### 리다이렉션 — 출력을 파일로
```bash
echo "hello" > a.txt              # 파일에 쓰기 (이미 있으면 덮어씀)
echo "world" >> a.txt             # 파일 끝에 덧붙이기
grep ERROR app.log > errors.txt   # 결과를 파일로 저장
```

## 4. 권한과 관리자 권한

### 권한 읽는 법
`ls -l` 결과의 `-rwxr-xr--` 는 **소유자 / 그룹 / 나머지**의 읽기(r) · 쓰기(w) · 실행(x) 권한입니다.

| 숫자 | 의미 |
|---|---|
| r = 4, w = 2, x = 1 | 합산해서 표기 |
| `7` = rwx | 읽기·쓰기·실행 |
| `6` = rw- | 읽기·쓰기 |
| `5` = r-x | 읽기·실행 |
| `4` = r-- | 읽기만 |

### `chmod` — 권한 바꾸기
```bash
chmod +x run.sh         # 실행 권한 추가
chmod 755 run.sh        # 소유자 rwx, 나머지 r-x
chmod 600 secret.key    # 소유자만 읽기·쓰기 (비밀 키에 흔함)
```

### `chown` — 소유자 바꾸기
```bash
sudo chown user file.txt
```

### `sudo` — 관리자 권한으로 실행
```bash
sudo 명령
```
> ⚠ 무슨 일을 하는 명령인지 이해하지 못한 채 `sudo`를 붙이지 마세요. 시스템 파일을 망가뜨릴 수 있습니다.

## 5. 프로세스와 시스템 상태

### `ps` — 실행 중인 프로세스
```bash
ps aux                  # 모든 프로세스 (사용자, PID, CPU, 메모리, 명령)
ps aux | grep java      # java 만 골라 보기
```

### `top` — 실시간 CPU·메모리 현황
```bash
top                     # 종료는 q
```
(`htop`을 설치하면 더 보기 좋습니다.)

### `kill` — 프로세스 종료
```bash
kill 12345              # 정상 종료 요청 (PID 사용)
kill -9 12345           # 강제 종료 (최후 수단)
```
PID는 `ps`나 `lsof`로 찾습니다.

### `df` — 디스크 여유 공간
```bash
df -h
```

### `du` — 폴더·파일이 차지하는 크기
```bash
du -sh .                # 현재 폴더 전체 크기
du -sh *                # 항목별 크기
```

## 6. 네트워크

### `curl` — 터미널에서 HTTP 요청 보내기 (백엔드 개발 필수)
```bash
curl https://example.com                        # GET 요청
curl -i https://example.com                     # 응답 헤더 포함
curl -I https://example.com                     # 헤더만
curl -v https://example.com                     # 요청·응답 과정을 자세히
curl -X POST http://localhost:8080/orders \
  -H "Content-Type: application/json" \
  -d '{"item":"book","qty":1}'                  # JSON 보내기
```

### `ping` — 서버가 응답하는지, 지연은 얼마인지
```bash
ping -c 4 example.com   # 4번만 (-c). 윈도우는 -n
```

### `lsof -i` — 어떤 프로그램이 어떤 포트를 쓰는지
```bash
lsof -i :8080           # 8080 포트를 쓰는 프로세스
lsof -i -P              # 열린 소켓 전체 (포트 번호를 숫자로)
```
> "포트가 이미 사용 중" 오류가 날 때 가장 먼저 쓰는 명령입니다.

### `netstat` — 네트워크 연결 상태
```bash
netstat -an | grep LISTEN       # 대기 중인 포트
netstat -rn                     # 라우팅표
```
리눅스 서버에서는 `ss -tulpn`을 더 자주 씁니다(맥에는 없음).

### `traceroute` — 목적지까지 거치는 라우터(홉)
```bash
traceroute example.com
```
윈도우는 `tracert`입니다.

### `dig` / `nslookup` — DNS 조회
```bash
dig example.com
nslookup example.com
```

### `ssh` / `scp` — 원격 서버 접속과 파일 복사
```bash
ssh user@192.0.2.10                      # 서버 접속
ssh -i ~/.ssh/key.pem user@192.0.2.10    # 키 파일로 접속
scp app.jar user@192.0.2.10:/home/user/  # 서버로 파일 보내기
```

## 7. 환경 변수와 설정

### 환경 변수
```bash
export DB_PASSWORD=secret     # 현재 터미널에서만 유효한 변수 설정
echo $DB_PASSWORD             # 값 확인
env                           # 전체 환경 변수 목록
which java                    # 실행되는 java 의 위치
```
> 비밀번호 같은 값을 **코드에 쓰지 않고 환경 변수로** 넘기는 것이 기본입니다.

### 영구 설정
터미널을 닫아도 유지하려면 설정 파일에 적습니다(맥은 `~/.zshrc`).
```bash
nano ~/.zshrc
source ~/.zshrc               # 바꾼 설정을 지금 터미널에 적용
```

### `history` — 지난 명령 목록
```bash
history | tail -20
```

## 8. 터미널 안의 에디터

서버에서 설정 파일을 고칠 때 씁니다.

### `nano` — 쉬운 편
| 키 | 동작 |
|---|---|
| 그냥 입력 | 편집 |
| `Ctrl + O`, Enter | 저장 |
| `Ctrl + X` | 종료 |

### `vim` — 서버에 거의 항상 있음
| 키 | 동작 |
|---|---|
| `i` | 입력 모드 (타이핑 가능) |
| `Esc` | 명령 모드로 돌아감 |
| `:wq` + Enter | 저장하고 종료 |
| `:q!` + Enter | **저장하지 않고** 종료 |
| `/단어` | 검색 |

## 9. 실전 시나리오

### 시나리오 1. 로그에서 오류 찾기
```bash
tail -f app.log                         # 실시간 로그 보기
grep -n "ERROR" app.log | tail -20      # 최근 오류 20개
grep -C 5 "NullPointerException" app.log # 앞뒤 5줄과 함께
```

### 시나리오 2. "포트가 이미 사용 중"일 때
```bash
lsof -i :8080                           # 누가 쓰는지 확인 (PID 확인)
kill 12345                              # 종료 (안 되면 kill -9)
```

### 시나리오 3. 디스크가 가득 찼을 때
```bash
df -h                                   # 어느 디스크가 찼는지
du -sh * | sort -h                      # 큰 폴더가 뭔지 (현재 위치에서)
```

### 시나리오 4. API가 잘 동작하는지 확인
```bash
curl -i http://localhost:8080/health
curl -X POST http://localhost:8080/login \
  -H "Content-Type: application/json" \
  -d '{"id":"test","pw":"1234"}'
```

### 시나리오 5. 서버가 느릴 때
```bash
top                                     # CPU·메모리를 많이 쓰는 프로세스
ps aux | grep java                      # 앱 프로세스 확인
df -h                                   # 디스크 여유
```

## 10. 맥과 리눅스 서버의 차이

| 항목 | 맥 | 리눅스 서버 |
|---|---|---|
| 기본 셸 | zsh | 보통 bash |
| 설정 파일 | `~/.zshrc` | `~/.bashrc` |
| 포트 확인 | `lsof -i`, `netstat` | `ss -tulpn` (`sudo` 필요할 때 있음) |
| `sed -i` | `sed -i '' 's/a/b/' f` (빈 따옴표 필요) | `sed -i 's/a/b/' f` |
| `ls` 색상 | `ls -G` | `ls --color` |
| 패키지 설치 | `brew install` | `apt install` (우분투), `yum`/`dnf` |

같은 이름의 명령도 **옵션이 다를 수 있으니** 서버에서는 `--help`를 확인하세요.

## 11. 안전하게 쓰는 습관

- `rm`, `mv`, `chmod`, `chown`, `kill`은 **대상을 `ls`로 먼저 확인**하고 실행하세요.
- `sudo`는 이유를 알 때만 쓰세요.
- 인터넷에서 복사한 명령은 **뜻을 이해하고** 붙여 넣으세요 (`curl ... | sh` 같은 형태는 특히 주의).
- 비밀번호, 키는 터미널 명령에 직접 쓰면 `history`에 남습니다. 환경 변수나 파일로 다루세요.
- 서버에서 작업하기 전에는 **백업**을 먼저 만드세요.

## 12. 연습 과제 (1주, 하루 20분)

| 날짜 | 과제 |
|---|---|
| 1일 | `pwd`, `ls -la`, `cd`로 폴더를 이동하며 구조 파악, `mkdir`, `touch`로 연습 폴더 만들기 |
| 2일 | `cp`, `mv`, `rm -i` 로 파일 복사·이동·삭제, `cat`, `less`, `head`, `tail` 로 파일 읽기 |
| 3일 | 샘플 로그 파일을 만들고 `grep -n`, `grep -v`, `wc -l`, 파이프로 조합하기 |
| 4일 | `find`로 큰 파일과 최근 수정 파일 찾기, `df -h`, `du -sh *` |
| 5일 | `ps aux`, `top`, `lsof -i`로 지금 컴퓨터에서 도는 프로세스와 열린 포트 보기 |
| 6일 | `curl -v` 로 웹사이트 요청 과정 읽기, `ping`, `traceroute`, `dig` 로 DNS와 경로 확인 |
| 7일 | `chmod`로 스크립트 만들어 실행하기, `export`로 환경 변수 쓰기, 하루 정리 |

> 막히면 `명령 --help`, `man 명령`, 검색 순서로 찾아보세요. 에러 메시지를 **그대로** 검색하는 것이 가장 빠릅니다.
